## 2. Bug 修复（P0 — 必须修复）

### BUG-004：私聊流式回复不合并

- **现象**：私聊窗口中 agent 的流式回复，每个 token 渲染为独立的一行，而不是原地更新
- **复现**：打开任意 agent 私聊 → 发送 steer 指令 → 观察回复区域
- **预期**：streaming token 应在同一行原地追加，和 ChatGPT/Claude 的打字机效果一致
- **验收**：agent 回复过程中，文本在同一段落内流式增长，无重复行

### CLI-1：`bossmode on` 未 fork 到后台

- **现象**：执行 `bossmode on` 后进程卡在前台，需要 Ctrl+C 才能回到 shell
- **预期**：CLI fork daemon 子进程后立即返回 shell，输出 `Bossmode started at http://... (PID xxx)`
- **验收**：`bossmode on` 执行后 1 秒内回到 shell prompt；`bossmode status` 显示运行中

### CLI-2：端口占用时静默失败

- **现象**：端口被占用时，CLI 仍输出 "starting at..."，但 daemon 实际未启动，无任何报错
- **原因**：CLI fork 后不等待 daemon 确认，daemon 的错误输出被丢弃（stdio: "ignore"）
- **预期**：CLI 等待 daemon 启动确认信号（如 ready 文件或 IPC），超时或失败时报错
- **验收**：端口被占用时，CLI 输出明确的错误信息 "Port xxxx is already in use"

### CLI-3：首次设置密码明文回显

- **现象**：首次运行交互式设置时，密码输入是明文显示的
- **预期**：密码输入时终端不回显（hidden input）
- **严重度**：中（单用户工具，安全风险较低，但体验不好）
- **验收**：密码输入时终端显示为空或 `*` 掩码

## 3. UI 改进 — 高优先级

### UI-1：左侧导航重设计

- **参考**：Claude 桌面端首页
- **目标**：
  - 清晰的功能分区（Rooms / Contacts 用 section header 分隔）
  - 可折叠的 section（点击 header 折叠/展开）
  - 视觉风格对齐 Claude 的简洁暗色调
  - Contacts 不再被挤到底部需要滚动
- **包含**：
  - UI-2（Contacts 空间优化）
  - UI-5（Sign out 移到左下角 + 用户信息，参考 Claude 左下角头像区域）
- **验收**：Rooms 和 Contacts 各自可折叠；4 个 agent 无需滚动即可全部可见；用户信息在左下角

### UI-10：Markdown 渲染 + 代码块语法高亮

- **参考**：Discord 消息渲染
- **范围**：群聊和私聊的 agent 消息
- **支持的格式**：
  - 粗体 `**text**`、斜体 `*text*`
  - 标题 `# ## ###`
  - 列表 `- item` / `1. item`
  - 行内代码 `` `code` ``
  - 代码块 ` ```language ... ``` ` + 语法高亮
  - 链接 `[text](url)`
- **验收**：agent 发送包含 markdown 的消息时，群聊中正确渲染为富文本；代码块有语法着色

### UI-11：时间戳改进

- **参考**：Discord 消息分组
- **设计**：
  - 日期分隔线："—— 2026年3月20日 ——"
  - 同一用户连续发言：只第一条显示头像和用户名，后续消息紧凑排列
  - Hover 时显示精确时间
- **验收**：跨天消息有日期分隔线；同一 agent 连续消息不重复显示名称

### UI-16：私聊从浮窗改为顶部 tab

- **设计**：
  - 进入 room 后，顶部区域有 tab 栏：`群聊 | pm | architect | ...`
  - 点击成员面板中的 agent → 打开该 agent 的私聊 tab
  - tab 可关闭（× 按钮）
  - 群聊 tab 不可关闭
  - 私聊和群聊是同一个 agent 的不同视角：群聊只显示发到聊天室的消息，私聊展示完整工作过程
- **验收**：点击 agent → 顶部出现新 tab → 切换查看 → 关闭 tab 回到群聊

### UI-17：私聊内容对话式展示

- **现状**：显示原始事件日志（Turn start、turn_end、Agent started、chat done 等）
- **目标**：以对话形式展示 agent 的工作过程
  - agent 思考过程 → 可折叠的"思考"卡片
  - 工具调用 → 可展开的卡片（工具名 + 参数摘要，展开看完整参数和结果）
  - agent 文本回复 → 正常消息气泡
  - 用户 steer 指令 → 用户消息气泡
- **验收**：私聊中看不到 "Turn start"、"turn_end" 等原始事件标签；工具调用显示为可交互卡片

## 4. UI 改进 — 中优先级

### UI-3：联系人在线状态

- **设计**：Contacts 列表中每个 agent 显示状态指示器（绿色圆点 = idle，橙色 = working）
- **注**：成员面板中已有绿色圆点但不区分状态，需要和实际 agent 状态联动
- **验收**：agent 被 @ 激活后，Contacts 和 Members 中的状态指示器变为 working 状态

### UI-4：群聊列表路径精简

- **现状**：显示完整路径 `/home/fish/dev/llm/bossmode`
- **目标**：只显示最后一两级目录，如 `llm/bossmode` 或 `bossmode`
- **验收**：路径长度明显缩短，关键目录名可辨识

### UI-6：空状态优化

- **现状**：中央显示 "Select a room or create a new one to get started"
- **目标**：增加 "Create your first room" 醒目按钮，引导新用户
- **验收**：空状态有可点击的创建按钮

### UI-9：创建群聊全选按钮

- **设计**：Members 列表上方增加 "Select All / Deselect All" 按钮
- **验收**：点击全选后所有 agent 被勾选，计数器更新

### UI-12：用户消息靠右

- **设计**：用户发送的消息靠右对齐（类似 iMessage/微信），agent 消息靠左
- **验收**：群聊中 "you" 的消息在右侧，agent 消息在左侧

### UI-14：消息支持图片

- **设计**：
  - 输入框支持粘贴/拖拽图片
  - 图片上传到服务端存储
  - 消息中内联展示图片缩略图，点击放大
- **验收**：粘贴截图 → 图片出现在消息中 → 其他窗口可见

### UI-15：输入框多行自动拉伸

- **现状**：输入多行内容时输入框高度不变
- **目标**：输入框随内容自动增高（最大高度限制，如 200px）
- **验收**：输入 3 行内容时输入框可见 3 行，不需要滚动

### UI-20：添加成员面板

- **参考**：Discord "邀请朋友加入" 面板
- **现状**：浏览器原生 `window.prompt` 弹窗
- **目标**：自定义 dialog，搜索框 + 联系人列表 + 每行"邀请"按钮
- **验收**：点击 "+ Member" → 显示可邀请的 agent 列表（排除已在群聊中的）→ 点击邀请 → 成员加入
