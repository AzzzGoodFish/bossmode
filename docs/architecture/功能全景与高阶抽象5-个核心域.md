# Bossmode 功能全景（产品视角）

**Last Updated**: 2026-06-11（v0.12.21）
**配套文档**：代码核实版见 `architecture/feature-inventory-code-verified-v0.12.21.md`（含每个功能的前端组件 / 后端路由）。本文是产品/用户视角，回答「用户能做什么、在哪做、价值是什么」。

---

## 一、产品一句话
Bossmode 是一个「AI 员工协作工作台」：你把多个 AI agent 编成团队，放进项目房间里，用群聊 + @激活的方式让它们协作完成工作，并用任务板、知识库、模型凭证统一管理。

---

## 二、用户功能清单（按用户旅程）

### 1. 登录与外壳
- Token 登录 / 登出。
- 桌面侧栏 + 移动端抽屉响应式布局。
- 主侧栏导航：Rooms / Members / Agents / Skills / Knowledge / All Tasks / Settings。

### 2. Room（工作室 / 群聊）—— 核心场景
- 创建 Room（选成员 + 工作目录 cwd）、重命名、删除。
- 群聊：用户与多个 agent 对话，`@名字` 激活指定成员，`@all` 广播。
- 私聊（1:1 Agent Activity）：查看单个 agent 的工作过程（thinking / 工具调用 / streaming）。
- 消息历史分页、消息搜索、消息范围检索。
- 成员面板：实时状态、context usage 进度条、token 用量。
- Room 内 tab：Chat | Tasks | 各 Agent 的 Activity。
- Room 设置：选 Rule、改名称、改工作目录。
- 消息信封（Message Envelope）+ 服务端 target 硬校验：保证 agent 知道消息来源、回复目标正确。

### 3. 私聊里的 Agent 控制
- Steer（追加指令）、Abort（中断）、Restart（保留 session 重启）、Reset session、查看 context usage。
- 实时 thinking 流 + 工具调用展示。

### 4. Members（房间里的 agent 实例）
- 创建（选 Agent + 模型 + 凭证 + thinking level）、编辑、删除。
- 跨房间状态查看。
- Thinking Level：off / minimal / low / medium / high / xhigh。
- **模型热切换**：运行中换模型/凭证，下一 turn 生效；跨 credential/provider 切换也支持（0.12.20 修复）。

### 5. Agents（员工定义 / 模板）
- 列表、详情/编辑、创建（基于模板）、删除。
- 定义 prompt、默认模型、skills、头像。
- 内置模板：pm / architect / developer / qa / designer / summarizer。

### 6. Skills
- 可复用技能文档，挂到 agent/member；列表、详情/编辑、模板。

### 7. Knowledge（文件系统化文档库）
- 文档 CRUD（Markdown 文件树 + 子目录），应用内编辑器（MDXEditor）。
- 移动 / 批量操作。
- Rule 选择性注入到 prompt。
- **Agent 改用文件系统工具（read/edit/write/bash）直接访问，旧 knowledge 工具已下线。**

### 8. Tasks（任务板 + Linear）
- 轻量看板：todo → in-progress → review → done。
- 评论、订阅者、引用文档、assignee（assign 不自动激活）。
- Reviewer workflow。
- 可选 Linear 双向同步。
- 入口：房间内 Tasks tab + 全局 All Tasks 页 + 任务详情页。

### 9. Model Credentials & Providers（模型凭证）
- **Connect Provider**：内置 catalog provider（api_key 或 OAuth）。
  - per-model 定制：`Enabled` 开关 + `Context window` 覆盖，抗 catalog 刷新（0.12.21）。
- **Custom Endpoint**：手动配模型（proxy / 本地 / 第三方），可改 contextWindow / maxTokens（0.12.18）。
- OAuth 登录 job、Fetch/discover models、Claude Code fingerprint 适配。
- Member 模型选择器。

### 10. Runtime 控制（进程内 pi SDK）
- 进程内 pi Agent SDK runtime（`@earendil-works/pi-coding-agent`）。
- Thinking level、Session Resume 全局开关、context usage 推送、模型热切换。
- 权威 agent_start/agent_end 状态监控。

### 11. 摘要（Summarization）
- 智能消息摘要（话题分段 Summary 卡片），手动/自动触发 + 阈值/保留数配置。
- Summarizer 可观测性。

### 12. 附件
- 流式上传（进度 + 取消）。
- 聊天内附件行：图片灯箱预览 / 文件下载。

### 13. 集成 — Linear
- 连接 Linear（team/project 绑定）、任务推送/同步、状态查看。

### 14. 内置团队版本更新
- 内置 agents/skills/rules 作为带版本的 team 发布；检查 / 应用 / 忽略更新。

### 15. Token 用量
- 按 member 统计 token 用量，Members 页展示。

### 16. 移动端
- 抽屉导航 + 顶栏 + 响应式布局。

## 三、高阶抽象 — 5 个核心域

| 域 | 本质 | 用户关心的问题 | 代码目录 |
|----|------|---------------|----------|
| **Workforce** | 做事的人（Agent+Skill+Member） | 有哪些员工？各自擅长什么？ | workforce/ |
| **Workspace** | 做事的地方（Room + Task） | 在哪个项目上工作？进展如何？ | workspace/ |
| **Knowledge** | 做事的背景（Knowledge+Rule） | 项目约定？协作规则？ | knowledge/ |
| **Communication** | 怎么交互（消息路由+WS+Envelope） | 消息怎么传递？@mention 怎么触发？ | communication/ |
| **Engine** | 底层怎么跑（Runtime+生命周期+摘要+模型凭证） | Agent 怎么执行？模型怎么接？ | engine/ |

## 五、关键洞察
1. Team 不是独立域，是 Workforce 的一部分（Team = Members + Rule）。
2. Knowledge 和 Rule 都是 Context，区别只是注入方式（tree index vs 全文注入）。
3. Room 是 Workspace 的核心实体（组合 Workforce + Context + 工作目录），Task 也归 Workspace。
4. Member 有两种类型：human（用户）和 agent，Human Member 不在 UI 成员面板显示。
5. Summarizer 是特殊 agent：临时进程 + 专用工具。
6. Model Credentials 已成为 Engine 域的重要一块（Connect Provider + Custom Endpoint + 热切换 + per-model 定制）。

## 六、给前端重构的提示（来自 architect 代码核实）
- 应用是**无路由库的单壳状态驱动 SPA**：`Layout` 按 `ActivePage` 切换，房间视图在 `Main` 自管 tab。IA 改造集中在 `Sidebar` + `Layout` + `Main`。
- `SettingsPage` 是一长页塞了 5 个板块（Credentials / Runtime / Summary / Linear / Team Updates），是 IA 重组首要候选。
- Model Credentials 编辑器已统一为 Custom-Endpoint 竖排卡片（0.12.21），作为模式参考。
